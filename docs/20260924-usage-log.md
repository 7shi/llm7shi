# Recording Token Usage in usage.jsonl

`Response.usage` (see [20260915-token-usage.md](20260915-token-usage.md)) reports token usage for one call. This document covers what comes after that: accumulating usage over a run, recording it in `usage.jsonl`, and reading the totals back. It is written for downstream CLIs built on llm7shi. The design rationale of each function lives in [llm7shi/usage.md](../llm7shi/usage.md) and the docstrings of `llm7shi/usage.py`; this document focuses on how the pieces fit together in a caller.

## The Log File

`usage.jsonl` holds one JSON object per line:

```json
{"timestamp": "2026-09-24T21:03:12.345678+09:00", "model": "openai:gpt-5.6-luna", "input_tokens": 1234, "output_tokens": 567, "reasoning_tokens": 320, "total_tokens": 1801}
```

- `timestamp` is timezone-aware local time; dates are grouped in UTC when reading
- `model` is whatever string the caller passes, normally the vendor-prefixed model name given on the command line
- The remaining keys are `Usage.to_dict()`: only the normalized fields, and only those the provider reported

The default location comes from `find_usage_file()`: `$XDG_STATE_HOME/llm7shi/usage.jsonl`, or `~/.local/state/llm7shi/usage.jsonl`. It is account-level rather than per-project because token quota is tracked per account/API key, so several projects writing to one file see one shared daily total. `find_usage_file(search_upward=True)` looks for a project-local `usage.jsonl` instead, for callers that want a separate log.

Writes and reads are serialized with a file lock, so concurrent processes (parallel `make -j` steps, several terminals) can append to the same file safely.

## Functions at a Glance

| Function | Role |
|----------|------|
| `Client.usages` | Every call's `Usage` on that client, including quality retries |
| `sum(usages)` / `+` | Summation of normalized fields across calls |
| `find_usage_file()` | Default path; creates nothing |
| `append_usage(usage, model, path)` | Append one record; creates the directory on first write |
| `print_today_totals(path, models=[...])` | Print today's (UTC) per-model totals under a `# {date} \| {path}` header |
| `parse_usage_file(path)` | `{date: {model: Usage}}` for custom reports |
| `merge_usage(path)` | Collapse records to one per UTC date and model |

## Typical Pattern

A CLI that makes one or more LLM calls, then records and shows the usage:

```python
import argparse
from pathlib import Path

from llm7shi import Client
from llm7shi.usage import append_usage, find_usage_file, print_today_totals

# Set to a path to record usage; None means "don't record"
USAGE_PATH = None


def main() -> int:
    parser = argparse.ArgumentParser()
    parser.add_argument("files", nargs="+", type=Path)
    parser.add_argument("-m", "--model", required=True)
    parser.add_argument("--save-usage", action="store_true",
                        help="Record usage regardless of the model")
    args = parser.parse_args()

    global USAGE_PATH
    if args.model.startswith(("openai:", "gpt-")) or args.save_usage:
        USAGE_PATH = find_usage_file()

    client = Client(model=args.model, keep_history=False, show_usage=True)

    try:
        for path in args.files:
            response = client(path.read_text())
            ...
    finally:
        # Record silently so an interrupted run still logs what it consumed;
        # the report below is printed only on normal completion.
        if client.usages and USAGE_PATH is not None:
            append_usage(sum(client.usages), args.model, USAGE_PATH)

    if client.usages:
        print(f"\n--- Total Usage ---\n{sum(client.usages)}")
        if USAGE_PATH is not None:
            print("")
            print_today_totals(USAGE_PATH, models=[args.model])
    return 0
```

The output of a two-call run looks like this (numbers illustrative):

```
...
Usage({'input_tokens': 1200, 'output_tokens': 540, 'total_tokens': 1740})
...
Usage({'input_tokens': 1350, 'output_tokens': 610, 'total_tokens': 1960})

--- Total Usage ---
Usage({'input_tokens': 2550, 'output_tokens': 1150, 'total_tokens': 3700})

# 2026/09/24 | ~/.local/state/llm7shi/usage.jsonl
openai:gpt-5.6-luna|input:12,345|output:6,789|total:19,134
```

### Collect in `client.usages`, Sum Once

`Client` appends each call's `Usage` to its `usages` list, so the caller does not keep its own running total. This matters for more than convenience: when `Client`'s quality check rejects a response (repetition, empty reply, invalid JSON) and regenerates it, the rejected attempt still consumed tokens, but the caller only ever receives the final `Response`. A total built from `response.usage` at the call site would miss those attempts; `client.usages` includes them. Responses whose provider reported no usage are skipped, so the list holds only real `Usage` objects.

`sum(client.usages)` works because `Usage` absorbs `sum()`'s implicit `0` start value, and `+` sums only the normalized fields, so the result is exactly what `append_usage()` writes anyway (see "Aggregating Usage Across Calls" in `llm7shi/usage.md`). `sum([])` would return a plain `0`, hence the `if client.usages:` guard, which also means nothing is printed or recorded when no call reported usage.

Appending once at the end keeps the log at one line per run instead of one per call, and matches what the user wants to see: how much this run cost.

### Record in `finally`, Report After It

Recording and reporting are split between two places:

- **Recording goes in `finally`.** `append_usage()` runs whether the loop finishes, raises, or is stopped with Ctrl+C (`KeyboardInterrupt`), because the tokens an interrupted run consumed were still spent. It prints nothing there: on an interrupt the user is leaving, and usage output would only get in the way of the traceback. If `append_usage()` itself fails there (disk full, permission error), its exception replaces the one already propagating; wrap it in `try`/`except` if the original error must stay visible.
- **Reporting goes after the `try`.** `--- Total Usage ---` and `print_today_totals()` are reached only on normal completion. An interrupted run's usage is not lost, only not shown; the next `print_today_totals()` (or `llm7shi usage show`) includes it.

A process killed without unwinding (`kill -9`, a crash of the interpreter itself) skips `finally` and records nothing. When that matters, append inside the loop instead (one record per call); `print_today_totals()` shows the same daily total either way, since it sums records on read.

### Three Levels of Output

Each level answers a different question, so all three are printed:

- **Per call**: `Client(show_usage=True)` prints each call's `Usage` right after its streamed output, which is how an unexpectedly expensive call (a long input, runaway reasoning) gets noticed as the run progresses. It prints every attempt, including quality retries, so the printed lines add up to the total below. Off by default so existing output is unchanged; a caller that wants a different format leaves it off and prints `response.usage` itself (that shows the final attempt only).
- **Per run**: `--- Total Usage ---` shows the sum for this run. It is printed whether or not usage is recorded, since knowing what a run cost is useful even for a local model that never goes into the log. Printed only when the run completes normally.
- **Per day**: `print_today_totals()` shows today's running total from the log, only when recording and only on normal completion.

When the calls are spread over helper functions, pass them the same client: per-call output comes from `show_usage`, nothing needs to be returned or threaded back, and `main()` sums `client.usages` at the end. A client made with `copy()` starts with an empty `usages` (so summing both never double-counts), which means a run using several clients sums each one's list.

### `USAGE_PATH = None`, Set According to the Model

The module-level `USAGE_PATH` starts as `None`, and `main()` sets it to `find_usage_file()` only after the arguments show that recording is wanted. Two reasons:

- **Record only what is metered.** The shared log exists to watch quota on paid APIs. Calls to a local Ollama or llama.cpp server cost nothing, and recording them would mix unmetered models into the account-level daily totals. The condition is a prefix check on the model name: `openai:`, plus `gpt-` because an unprefixed model name other than `gemini*` is routed to OpenAI (see `compat.py`), so `gpt-4.1-mini` alone is also a metered OpenAI call. Extend it with the providers you pay for, and keep `--save-usage` for the occasional exception.
- **One switch for the whole program.** `None` versus a path is the single decision point. Code that appends or prints usage checks `USAGE_PATH is not None` instead of re-deriving the condition from the model name, and a helper function deep in the program can consult the same global without threading a flag through every call. Tests or other entry points can also set it directly.

`find_usage_file()` creates nothing, so calling it is free; the directory appears only when `append_usage()` first writes.

### Show Only the Models This Run Used

Because the file is shared across projects, today's totals may include models the current CLI never called. Passing `models=[args.model]` to `print_today_totals()` restricts the output to the model this run used, so the line printed after a run answers "how much have I used of *this* model today". The header line includes the file path, which makes it visible when a project-local file was picked up instead of the account-level one.

## Checking and Maintaining the Log

`llm7shi` installs the `llm7shi` command, whose `usage` subcommand handles the log, so one `uv tool install git+https://github.com/7shi/llm7shi.git` makes it available everywhere without adding a console script to each project:

```
$ llm7shi usage show                     # today's totals, all models
$ llm7shi usage show -m openai:gpt-5.6-luna
$ llm7shi usage show -a                  # every date plus a grand total
$ llm7shi usage merge                    # collapse to one line per UTC date and model
$ llm7shi usage -f ./usage.jsonl show    # a file other than the default
```

`uv run llm7shi usage ...` is equivalent inside a project that depends on llm7shi.

`merge` is optional and idempotent. It shrinks a file that has grown with one record per call, at the cost of per-call detail within each day, so it is left to the user rather than done automatically.
